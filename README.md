**# CS-230-Operating-Platforms.**# CS 230 Portfolio – The Gaming Room

## Briefly summarize The Gaming Room client and their software requirements.

The Gaming Room was a client that wanted to expand their Android game, *Draw It or Lose It*, into a web-based application that could work across multiple platforms. The software needed to support multiple games, teams, and players while keeping names and IDs unique. It also needed to be scalable, secure, and accessible from different operating systems and devices.

## What did you do particularly well in developing this documentation?

I think I did well comparing the different operating platforms and explaining why Linux would be a strong option for the server. I also clearly described how the application could use a distributed architecture while still supporting users on Windows, macOS, Linux, and mobile devices.

## What about the process of working through a design document did you find helpful when developing the code?

The design document helped me organize the requirements before focusing on the code. Breaking the system into classes, relationships, storage, security, and networking requirements made it easier to understand how the different parts of the application should work together.

## If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

I would improve the system architecture section by adding a more detailed visual showing how the browser, application server, database, and storage services communicate. This would make the design easier for both developers and nontechnical users to understand.

## How did you interpret the user’s needs and implement them into your software design? Why is it so important to consider the user’s needs when designing?

I focused on the client's need to support more users and platforms without creating a completely separate application for every operating system. Designing the game as a browser-based application allows users to access it from many different devices. Considering user needs is important because the software should solve the client's actual problems and be easy for their users to access and use.

## How did you approach designing software? What techniques or strategies would you use in the future?

I started by identifying the requirements and then breaking the application into smaller components. I compared different platforms, considered scalability and security, and used object-oriented design principles to organize the system. In the future, I would continue using design documents, UML diagrams, and requirement analysis before beginning development because they help identify problems early and create a clearer plan for the application.
